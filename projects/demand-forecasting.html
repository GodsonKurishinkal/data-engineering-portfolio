Case study 4 of 6 · Forecasting

Demand forecasting by demand pattern

Each SKU is classified by ADI/CV² as smooth, erratic, intermittent or lumpy. The class decides which models are tried, and backtesting picks one model per SKU. Runs on one machine for 30,000+ SKUs.

01

The problem

The previous process applied one simple moving average to every SKU. A product that sells every day and a part ordered once a month behave differently, and one method does not fit both.

  • Stockouts on fast movers.
  • Excess stock on slow movers.
  • Planners overriding forecasts by hand.
  • No record of why a forecast missed.
02

What I built

Every SKU goes through the same steps: read two years of daily sales, classify the demand pattern, select a model, forecast 30 days ahead with an interval, and pass the result to planning.

03

ADI / CV² pattern classification

Two measures describe a demand series well enough to choose a modelling approach:

  • ADI, average demand interval: how often demand occurs.
  • CV², squared coefficient of variation: how much the size varies when it does.

The standard thresholds (ADI 1.32, CV² 0.49) split SKUs into four patterns. Each pattern has its own shortlist of models.

Smooth

ADI < 1.32 · CV² < 0.49
Regular demand with stable size.
ARIMA · Prophet · Holt-Winters

Erratic

ADI < 1.32 · CV² ≥ 0.49
Frequent demand with highly variable size.
Random Forest · XGBoost

Intermittent

ADI ≥ 1.32 · CV² < 0.49
Infrequent demand with consistent size.
Croston · SBA · TSB

Lumpy

ADI ≥ 1.32 · CV² ≥ 0.49
Infrequent demand with variable size. Hard to forecast; safety stock carries most of the load.
TSB · safety stock
04

The model set

Nine models. A SKU's pattern maps to a shortlist, and a rolling-origin backtest picks one model from it. The mapping from pattern to shortlist is written down, not learned.

  • ARIMA, Prophet, Holt-Winters: time-series models for smooth demand with trend and seasonality.
  • XGBoost, Random Forest: tree models on calendar and lag features, for erratic demand.
  • Croston, SBA, TSB: methods designed for intermittent and lumpy demand.
  • Simple exponential smoothing: the baseline every other model is compared against.
05

Key decisions

Decision 01

Classify first, then model

A single large model for all SKUs would be harder to run and harder to explain. Classifying first makes the selection auditable: a planner can see why a SKU got Croston and not ARIMA.

Trade-off: a SKU near a threshold can land in the wrong class and get a worse shortlist.

Decision 02

Explainability over accuracy

Planners use forecasts they understand. Each forecast is shown with its pattern and the model that produced it.

Trade-off: some accuracy is given up compared with a less transparent model.

Decision 03

Safety stock as an output

Every forecast comes with a prediction interval and a recommended safety stock, because planning needs the range and not only the point.

Trade-off: more columns in the output table for consumers to handle.

Decision 04

Backtest every release

Rolling-origin backtests run on every release. A model is selected on holdout windows, not on training metrics.

Trade-off: releases are slower.

06

Implementation

The classifier is one small function: a demand series in, a pattern label out. Selection and forecasting depend on it. Simplified illustration:

forecast/pattern_classifier.py Python scroll → 
from enum import Enum
import pandas as pd

class DemandPattern(Enum):
    SMOOTH = "smooth"
    ERRATIC = "erratic"
    INTERMITTENT = "intermittent"
    LUMPY = "lumpy"

class PatternClassifier:
    """Classify a demand series by its ADI/CV² signature."""

    def __init__(self, adi_threshold: float = 1.32, cv2_threshold: float = 0.49):
        self.adi_threshold = adi_threshold
        self.cv2_threshold = cv2_threshold

    def classify(self, demand: pd.Series) -> DemandPattern:
        non_zero = (demand > 0).sum()
        if non_zero == 0:
            return DemandPattern.LUMPY

        adi = len(demand) / non_zero
        values = demand[demand > 0]
        cv2 = (values.std() / values.mean()) ** 2

        high_adi = adi >= self.adi_threshold
        high_cv2 = cv2 >= self.cv2_threshold

        if not high_adi and not high_cv2: return DemandPattern.SMOOTH
        if not high_adi and     high_cv2: return DemandPattern.ERRATIC
        if     high_adi and not high_cv2: return DemandPattern.INTERMITTENT
        return DemandPattern.LUMPY

07

Results

  • Each SKU is forecast by a model chosen for its demand pattern, replacing one moving average for everything.
  • Intermittent and lumpy SKUs are forecast with Croston, SBA or TSB.
  • Every forecast carries its pattern, its model, a prediction interval and a recommended safety stock.

Accuracy and stockout figures are not published here because the metric definitions and baselines are not yet written up.

08

What I'd do differently

Hierarchical forecasts

Some SKUs are too sparse to model alone. Forecasting at category level and reconciling downwards would help the long tail.

Continuous model comparison

Selection happens per release. Running the next-best model in shadow between releases would show drift sooner.

Lead with intervals

Planners ask about the worst case more than the point forecast. The interval should have been the main output from the start.

Promotions as features

Promotional effects are applied after the forecast. They belong in the model as features.
