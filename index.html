How I build

Five rules I work by, each with the write-up where it applies.

01
Block bad data instead of logging it

A check that can be skipped will eventually be skipped. A schema violation stops the batch before it reaches the cleaned layer.

Three-tier data-quality checks
02
Fail at install time

A dependency cycle is visible in the config file. It should be rejected when the schedule is installed, not found at night through a wrong report.

Job scheduling with install-time validation
03
Write down what each choice costs

Every technical decision has a cost. Each decision record states the alternatives and what the choice gave up.

Seven decision records
04
Use the simple tool

Task Scheduler instead of Airflow, plain Parquet instead of Delta, three simple validation tiers instead of one model. Each choice is written down with the condition for moving off it.

Bronze/Silver/Gold lakehouse on Parquet
05
Keep fragile parts simple

A screen-automation bot is the least reliable part of a pipeline, so it only downloads the file. Parsing and business logic run downstream, where a failure is cheap to re-run.

Browser automation for systems without APIs
